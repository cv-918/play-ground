# 스킬 시스템 회귀 테스트 체크리스트

## 0. 문서 목적

본 문서는 스킬 시스템 전면 재설계 이후 아래 항목이 유지되는지 확인하기 위한 회귀 테스트 체크리스트다.

- 그래프 정의 기반 스킬 로딩이 정상 동작하는지
- 공통 런타임, 공통 효과 시스템, 공통 피격 경로가 스킬별 예외 없이 유지되는지
- 기존 4개 스킬의 기획 의도가 실제 플레이에서 보장되는지
- UI, 저장값, 씬 전환, 정리(cleanup)에서 구조 회귀가 없는지

---

## 1. 테스트 기본값

| 항목 | 값 |
| --- | --- |
| 대상 빌드 | `Debug|x86` |
| 스킬 정의 파일 | `Data/Skill.json` |
| 대상 스킬 ID | `0: 먼지 돌풍`, `1: 부식`, `2: 다크사이트`, `3: 보풀 위성` |
| 판정 기록 | `Pass / Partial / Fail` |
| 근거 기록 | 영상, 캡처, 로그, 코드 위치 중 최소 1개 |

### 공통 사전 조건

- 플레이어가 4개 스킬을 모두 장착한 상태로 시작한다.
- 스킬 쿨다운 UI가 보이는 상태에서 테스트한다.
- 피격 반응과 넉백이 확인 가능한 적을 같은 스테이지에서 준비한다.
- 이동 중, 정지 중, 피격 직후, 대시 직후 상황을 각각 재현할 수 있어야 한다.

| --- | --- | --- | --- | --- |
| EX-00 | 예시 | Pass | 영상 00:10 | 없음 |

## 2. 정적 구조 회귀 체크

아래 항목은 실행 전 코드/데이터 확인용이다.

| ID | 체크 항목 | 기대 결과 | 확인 위치 |
| --- | --- | --- | --- |
| ST-01 | 스킬 정의가 `Skill.json`에서 로드되는가 | 런타임이 JSON 그래프 정의를 사용한다 | `Project/App/PlayGround.cpp`, `Project/Gameplay/GamePlaySystems/Json/SkillDefinitionDataManager.cpp` |
| ST-02 | 스킬 ID별 생성 `if/switch`가 제거되었는가 | 스킬 생성 시 ID 분기 대신 정의 기반 생성만 사용한다 | `Project/Gameplay/GamePlaySystems/SkillManager.cpp` |
| ST-03 | 스킬별 orchestration 클래스 의존이 제거되었는가 | `SkillBase`가 공통 런타임으로 동작하고 개별 스킬 클래스에 의존하지 않는다 | `Project/Gameplay/GamePlaySystems/Skills/SkillBase.cpp` |
| ST-04 | 실행체가 공통 actor로 통합되었는가 | `ProjectileExecutionActor`, `AreaFieldExecutionActor`, `OrbitExecutionActor`만 사용한다 | `Project/Gameplay/GamePlaySystems/Skills/SkillExecutionActors.*` |
| ST-05 | 히트 정책이 실행체 밖의 공통 런타임으로 분리되었는가 | 대상별 1회 제한, enter only, interval 판정이 `HitPolicyRuntime`에서 관리된다 | `Project/Gameplay/GamePlaySystems/Skills/SkillExecutionActors.*` |
| ST-06 | 상태 이상과 버프가 공통 효과 시스템으로 들어가는가 | `GameplayEffectController`가 상태와 modifier를 관리한다 | `Project/Gameplay/Components/GameplayEffectController.*` |
| ST-07 | 피해가 공통 피격 경로를 따르는가 | 직접 피해 대신 `HitContext -> ApplyHit` 흐름을 유지한다 | `Project/Gameplay/Components/Combat.cpp`, `Project/Gameplay/Actors/UnitBase.cpp` |
| ST-08 | `Movement::SetEnable(false)`로 Root/시전 제어를 하지 않는가 | 이동 입력 차단과 Root가 별도 제어점으로 처리된다 | `Project/Gameplay/Components/Movement.*` |
| ST-09 | 스킬 데이터, 런타임, 실행 책임이 분리되는가 | 정의는 JSON/definition, 상태는 runtime, 월드 잔류체는 execution actor가 담당한다 | `SkillDefinitionDataManager`, `SkillBase`, `SkillExecutionActors` |
| ST-10 | 신규 스킬 추가 시 수정 지점이 제한되는가 | 이상적으로 `Skill.json` 정의 추가와 공용 노드 확장만으로 끝난다 | 코드 리뷰 확인 |

## 9. 완료 기준

아래 조건을 모두 만족하면 이번 전면 재설계 범위의 1차 회귀를 통과한 것으로 본다.

- ST 항목이 모두 `Pass`다.
- 4개 스킬 핵심 기능 항목에 `Fail`이 없다.
- 공통 기능 항목에서 UI, cleanup, 저장값 호환 문제가 없다.
- 경계 상황 항목에서 크래시, 실행체 유령 판정, 상태 복원 실패가 없다.
- `Partial` 또는 관찰상 우연히 맞는 동작은 별도 이슈로 분리해 구조 보강 후보에 등록한다.
