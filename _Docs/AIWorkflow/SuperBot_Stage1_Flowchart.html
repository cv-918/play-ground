Super Bot Stage 1: 작업 지시 → 완료 전체 플로우

Hermes 계층과 Workflow / Repo Harness 계층이 언제 개입하는지 한 화면에서 추적하기 위한 시각 자료
Hermes: 직원 정체성 / 행동 원칙 / 도구 실행 Workflow: repo 법 / 승인 / 문서 산출물 / 검증 규칙 Both: 양쪽이 함께 판단 Tool: file / terminal / web 등 실제 실행 Gate: 중단 / 질문 / 재승인 지점
핵심 원칙: Super Bot Stage 1은 하위직원이 없는 단일 end-spec 직원이다. 직접 수행 가능한 일은 직접 수행하되, workflow 계층의 승인 scope, 설계/진행/완료 기록, 검증 규칙을 따른다.

End-to-End Main Flow

Hermes1. Super Bot identity loads

단일 S급 직원. 하위직원 없는 Stage 1에서는 직접 수행 원칙 적용.

Hermes2. Universal AI Staff Behavior

Think Before Acting, Signal Uncertainty, Simplicity, Surgical Scope, Evidence, Permission Boundary.

Workflow3. Repo law loads

AGENTS.md, AIWorkflow 문서, Work Packet / ActiveTask / Handoff 계약 확인.

Both4. Intake

goal, scope, non-goals, success criteria, risk, affected area로 작업을 재정의.

Gate5. Ambiguity gate

구현/권한/검증에 영향이 있는 모호성은 없어질 때까지 질문.

불명확
질문 → Intake로 복귀
명확
상태 조사로 진행

Tool6. Inspect actual state

git status, 관련 파일, 기존 패턴, 로그, 문서를 실제 도구로 확인.

Gate7. Approved scope gate

승인된 scope가 없으면 plan을 만들고 승인 요청. 있으면 문서화로 진행.

Workflow8. Design / Plan document

기본 위치: _Docs/AIWorkflow/Studio/WorkOrders/. 구현 전 작성.

Both9. Plan review

scope, final-form architecture, simplicity, risks, validation, permission boundary 재검토.

Gate10. Protected-change gate

schema/save-load/build/workflow/runtime architecture 등 scope 밖 보호 영역이면 중단 후 재승인.

Tool11. Execute bounded work

file/patch/terminal/web 등으로 승인 scope 안에서만 실행.

Workflow12. Progress record

기본 위치: _Docs/AIWorkflow/Studio/RoleRuns/. 판단, 명령, 파일, 막힘, scope 신호 기록.

Tool13. Verification

빌드/테스트/로그/수동검증 항목 확인. 못 한 검증은 미수행으로 기록.

Both14. Self-review

diff와 결과를 Critical/Major/Minor/Optional로 검토. 검증 없는 확신 금지.

Workflow15. Completion record

기본 위치: _Docs/AIWorkflow/Studio/ResultReviews/. 완료 내용, 검증, 리스크, metadata 기록.

Workflow16. Verification evidence placement

검증 후 같은 산출물을 업데이트할지, final report에만 증거를 남길지 scope에서 먼저 결정.

Workflow17. Design-vs-completion gap

최초 설계와 실제 결과 차이, scope deviation, reapproval needed, 행동 개선안을 분리 기록.

Workflow18. DevLog if required

FixLog / WorkLog / Retrospective 중 성격에 맞게 기록.

19. Final report + human decision

변경 요약, 검증 결과, 미검증, 리스크, 커밋/수동테스트/승인 필요 여부 보고.

Batch 6 보강 규칙

MetadataProgress / Completion 추적성

가능하면 timestamp/date, acting agent, session/channel, WorkOrder/Task ID, 관련 artifact/evidence link를 기록.

GapCompletion gap 안전 필드

scope deviation, reapproval needed, executed/unexecuted verification, remaining risks, human decisions, commit recommendation을 분리.

EvidencePost-verification update scope

검증 후 같은 ResultReview를 업데이트하려면 그 second write가 승인 scope에 포함돼야 함. 아니면 최종 검증 증거는 final report에 남김.

한 줄 요약

Hermes는 “직원이 어떻게 생각하고 도구를 쓰는가”를 담당하고, Workflow / Repo Harness는 “이 repo에서 무엇이 허용되고 어떤 산출물/검증 증거를 남겨야 하는가”를 담당한다. Super Bot은 두 계층의 교차점에서 직접 작업을 수행한다.
