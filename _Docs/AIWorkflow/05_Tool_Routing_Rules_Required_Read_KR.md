# 05_Tool_Routing_Rules 필수 확인 섹션 번역본

이 문서는 `05_Tool_Routing_Rules.md`에서 사용자가 반드시 직접 읽어야 하는 핵심 섹션을 한국어로 번역한 보조 문서다.

원본 운영 문서는 영어로 유지한다.  
이 문서는 어떤 도구를 언제 써야 하는지 빠르게 확인하기 위한 읽기용 문서다.

---

# 2. Core Principle — 핵심 원칙

핵심 원칙은 다음이다.

```text
현재 책임을 안전하게 완료할 수 있는 가장 작은 도구를 사용한다.
```

의미는 다음과 같다.

- 추론, 계획, 리뷰 기준, 검증 기준, 문서화는 ChatGPT를 사용한다.
- 저장소 컨텍스트가 필요하면 Codex를 사용한다.
- 승인된 로컬 파일 편집이 필요하면 GitHub Copilot Agent Mode를 사용한다.
- AI 편집보다 사람이 정확히 고치는 것이 안전하면 직접 구현한다.
- 상태 확인, diff, 롤백, 커밋 경계는 Git을 사용한다.
- 수동 워크플로우가 안정화되기 전에는 무거운 자동화를 도입하지 않는다.

# 4. ChatGPT

## 주 역할

ChatGPT는 오케스트레이터 관점의 추론과 문서화 도구다.

ChatGPT를 사용할 작업은 다음과 같다.

- 오케스트레이션
- 아키텍처 판단
- 범위 정의
- 위험도 평가
- 리뷰 기준
- 검증 기준
- 문서 초안 작성
- 프롬프트 생성
- 워크플로우 규칙 업데이트
- 의사결정 보조

ChatGPT는 로컬 실행 환경이 아니다.

## ChatGPT를 사용할 때

다음이 필요하면 ChatGPT를 사용한다.

- 구조화된 추론
- 아키텍처 비교
- 최종형과 축소 범위 계획
- 책임 경계 정의
- 워크플로우 문서 생성
- 리뷰 체크리스트 생성
- 검증 체크리스트 생성
- Copilot 또는 Codex 프롬프트 생성
- 사용자용 한국어 설명
- 영어 운영 문서 초안 작성

## ChatGPT로 하면 안 되는 것

ChatGPT가 다음을 할 수 있는 것처럼 취급하면 안 된다.

- 제공되지 않은 로컬 파일 직접 검사
- 로컬 저장소 수정
- Visual Studio 빌드 실행
- 테스트 실행
- 실제 Git 상태 확인
- 런타임 동작 검증
- Copilot 또는 Codex가 작업을 완료했는지 확인
- 사용자 증거 없이 로컬 실행이 일어났다고 주장

# 5. Codex

## 주 역할

Codex는 저장소 인식 분석과 구현 계획 도구다.

실제 저장소 컨텍스트가 중요할 때 사용한다.

Codex가 특히 유용한 경우는 다음이다.

- 기존 파일 구조 확인
- 기존 클래스 이름 확인
- 현재 책임 경계 확인
- 실제 호출 흐름 확인
- 관련 소스 파일 확인
- Git diff 확인
- 빌드 오류 분석
- 코드베이스 특화 구현 리스크 확인

## Codex를 사용할 때

다음 상황에서 Codex를 사용한다.

- ChatGPT가 현재 저장소 구조를 모르는 경우
- 파일 단위 계획에 실제 코드 컨텍스트가 필요한 경우
- 통합 지점 후보가 여러 개인 경우
- 기능이 여러 파일을 건드릴 수 있는 경우
- 기존 클래스, 함수, 데이터 구조 확인이 필요한 경우
- diff에 코드베이스 문맥이 필요한 경우
- Copilot 결과를 독립적으로 리뷰해야 하는 경우
- 구현 전에 저장소 분석이 필요한 경우

## Codex 권한 모드

Codex 사용은 명시적으로 다음 중 하나로 구분해야 한다.

```text
Read-only analysis
Implementation planning
Patch generation
Diff review
Build error analysis
```

기본 모드는 다음이어야 한다.

```text
Read-only analysis
```

쓰기나 패치 생성은 명시적 사용자 승인이 필요하다.

# 6. GitHub Copilot Agent Mode

## 주 역할

GitHub Copilot Agent Mode는 제한된 로컬 구현 실행자다.

승인된 변경을 로컬 프로젝트 파일에 적용해야 할 때 사용한다.

Copilot에는 제한된 구현 프롬프트를 전달해야 한다.

## Copilot Agent Mode를 사용할 때

다음 조건에서 사용한다.

- 아키텍처와 범위가 승인됨
- 수정 허용 파일이 정의됨
- Non-goals가 정의됨
- 실제 파일 편집이 필요함
- 구현 범위를 제한할 수 있음
- 사용자가 결과 diff를 리뷰할 수 있음
- 빌드 오류를 로컬에서 수정해야 할 수 있음

## Copilot 프롬프트에 반드시 포함할 것

모든 Copilot 구현 프롬프트에는 다음이 포함되어야 한다.

- 목표
- 승인된 설계 요약
- 생성 허용 파일
- 수정 허용 파일
- 수정 금지 파일
- 필요한 변경
- 금지 변경
- Non-goals
- 기대 출력
- 검증 메모
- 중단 조건

## Copilot Agent Mode를 쓰면 안 되는 경우

다음 상황에서는 사용하지 않는다.

- 아키텍처가 승인되지 않음
- 범위가 불명확함
- 수정 허용 파일이 불명확함
- 넓은 재설계를 요구하는 작업임
- 예상 diff가 리뷰하기 너무 큼
- 사용자가 런타임 동작을 검증할 수 없음
- 분석만 해야 하고 실행은 필요 없음

# 7. Manual Implementation — 직접 구현

## 주 역할

직접 구현은 사람이 AI 편집보다 더 안전하고 빠르고 정확하게 제어할 수 있을 때 사용한다.

직접 구현은 여전히 정식 실행 경로다.

AI 지원은 개발자가 직접 더 작고 안전하게 고칠 수 있는 경우까지 대체할 필요가 없다.

## 직접 구현을 사용할 때

다음 상황에서 직접 구현한다.

- 변경이 작고 명확함
- 필요한 수정이 정밀함
- AI가 과도하게 수정할 위험이 이득보다 큼
- 개발자가 코드 형태를 정확히 제어하고 싶음
- 민감한 생명주기 코드를 건드림
- 탐색적 또는 임시 변경임
- 도구에게 설명하는 것보다 직접 고치는 것이 쉬움

## 직접 구현만으로 끝내면 안 되는 경우

다음 경우에는 직접 구현을 하더라도 오케스트레이터 워크플로우로 범위, 리뷰, 검증, 문서화를 정의해야 한다.

- 아키텍처 경계에 영향
- 여러 시스템 관련
- 데이터 스키마 변경
- 리뷰 기준 필요
- 검증 기준이 단순하지 않음
- Dev Log가 필요함

# 8. Git

## 주 역할

Git은 안전장치와 추적성 도구다.

Git은 다음에 사용한다.

- 작업 트리 상태 확인
- diff 리뷰
- 변경 격리
- 롤백
- 커밋 경계
- 이력 추적
- 파일 이동 가시화

AI 보조 워크플로우에서 Git은 선택 사항이 아니다.

## 필수 Git 확인

AI 보조 구현 전:

```bash
git status
```

AI 보조 구현 후:

```bash
git status
git diff
```

커밋 전:

```bash
git status
git diff --cached
```

## 진행하면 안 되는 경우

다음 상황에서는 진행하지 않는다.

- 관련 없는 미커밋 변경이 있음
- diff에 예상하지 못한 파일이 포함됨
- AI가 승인 범위 밖 파일을 변경함
- 사용자가 diff를 설명할 수 없음
- 빌드 또는 검증이 실패했는데 커밋을 고려 중임

# 9. Build / Test Tools — 빌드 / 테스트 도구

## 주 역할

빌드와 테스트 도구는 실제 프로젝트 동작을 검증한다.

컴파일과 런타임 유효성은 빌드와 테스트로만 확인할 수 있다.

AI는 빌드와 런타임 검증을 대체할 수 없다.

## 빌드 / 테스트 도구를 사용할 때

다음 상황에서 사용한다.

- 소스 코드 변경
- 프로젝트 파일 변경
- 런타임 동작 변경
- 데이터 로딩 변경
- AI 생성 구현 적용
- 버그 수정 완료 판단
- 리팩토링 완료 판단

## 사용자 액션

사용자는 적절한 로컬 확인을 직접 실행해야 한다.

예시:

- Visual Studio 빌드
- 게임 런타임 스모크 테스트
- 수동 게임플레이 흐름 확인
- 데이터 로딩 시나리오 확인
- 회귀 시나리오 확인
- 디버그 로그 확인

어시스턴트는 무엇을 테스트해야 하는지 정의할 수 있다.  
하지만 사용자가 결과를 제공하지 않는 한 테스트가 통과했다고 말하면 안 된다.

# 11. Future Automation Tools — 미래 자동화 도구

미래 자동화 도구 후보는 다음과 같다.

```text
Codex CLI
OpenAI Agents SDK
LangGraph
MCP
Claude Code
Gemini CLI
Custom local orchestrator scripts
```

이 도구들은 초기 필수 범위 밖이다.

문서 기반 및 반자동 워크플로우가 안정된 뒤 평가한다.

## 미래 자동화 도구를 검토할 때

다음 조건을 만족하면 검토한다.

- 수동 워크플로우가 안정적임
- 프롬프트 템플릿이 검증됨
- 승인 게이트가 명확함
- 반복 작업이 예측 가능함
- 빌드와 검증 명령이 신뢰 가능함
- Git 롤백 습관이 확실함
- 도구 실패를 진단할 수 있음

## 미래 자동화 도구를 쓰면 안 되는 경우

다음 상황에서는 도입하지 않는다.

- 워크플로우 규칙이 아직 자주 바뀜
- 승인 게이트를 명확히 정의하지 못함
- 빌드 / 테스트 검증이 수동이고 불안정함
- 저장소 구조가 불안정함
- 목적이 단지 유행을 따라가는 것임
- 도구 추가가 생산성보다 혼란을 더 키움

# 12. Tool Routing Matrix — 도구 라우팅 매트릭스

| 작업 필요 | 추천 도구 |
|---|---|
| 아키텍처 판단 | ChatGPT |
| 워크플로우 문서 초안 | ChatGPT |
| 사용자용 한국어 설명 | ChatGPT |
| 저장소 구조 분석 | Codex |
| 기존 코드 흐름 분석 | Codex |
| 코드베이스 기반 구현 계획 | Codex, 이후 ChatGPT 리뷰 |
| 승인된 로컬 파일 편집 | GitHub Copilot Agent Mode |
| 작고 정밀한 수정 | 직접 구현 |
| 빌드 검증 | 빌드 도구 / Visual Studio |
| 런타임 검증 | 수동 테스트 / 게임 런타임 |
| diff 리뷰 | Git, ChatGPT, 저장소 문맥 필요 시 Codex |
| 커밋 경계 | Git |
| Dev Log 생성 | ChatGPT, Markdown 저장 |
| 프롬프트 생성 | ChatGPT |
| 반복 자동화 | 워크플로우 안정화 이후 미래 자동화 도구 |

# 13. Routing Decision Questions — 도구 선택 전 질문

도구를 선택하기 전에 다음을 묻는다.

```text
1. 이 작업에 저장소 컨텍스트가 필요한가?
2. 이 작업에 로컬 파일 편집이 필요한가?
3. 이 작업에 빌드 또는 런타임 실행이 필요한가?
4. 아키텍처가 이미 승인되었는가?
5. 구현 범위가 제한되어 있는가?
6. 사용자가 diff를 리뷰할 수 있는가?
7. 직접 구현이 더 안전한가?
8. 결과를 영속 문서로 남겨야 하는가?
9. 도구가 필요해서 쓰는 것인가, 아니면 그냥 있기 때문에 쓰는 것인가?
```

# 14. Default Routing Policy — 기본 라우팅 정책

불확실할 때는 다음 기본 정책을 사용한다.

```text
추론 우선: ChatGPT
저장소 검사: Codex
승인된 구현: Copilot 또는 직접 구현
검증: 빌드 / 테스트 도구
변경 추적: Git
지속 기록: Markdown
```

저장소 컨텍스트가 부족하면 세부사항을 지어내지 않는다.

구현 범위가 승인되지 않았다면 Copilot으로 보내지 않는다.

빌드 / 테스트 증거가 없다면 작업 완료로 표시하지 않는다.

# 15. Anti-Patterns — 금지 패턴

다음 도구 라우팅 패턴은 금지한다.

## 15.1 아키텍처 승인 전 Copilot 사용

아키텍처와 범위가 승인되기 전에 Copilot Agent Mode를 사용하는 것.

위험:

- 통제되지 않은 수정
- 책임 누수
- 넓은 리팩토링
- 리뷰하기 어려운 diff

---

## 15.2 ChatGPT가 실행한 척하기

ChatGPT가 사용자 증거 없이 로컬 파일을 검사했거나, 빌드를 실행했거나, 런타임 동작을 검증했다고 주장하는 것.

위험:

- 잘못된 확신
- 잘못된 완료 처리
- 실패 누락

---

## 15.3 모든 것에 Codex 사용

저장소 컨텍스트가 필요하지 않은 작업에도 Codex를 사용하는 것.

위험:

- 도구 오버헤드
- 컨텍스트 노이즈
- 느린 워크플로우

---

## 15.4 너무 이른 무거운 자동화

수동 승인 게이트, 검증 규칙, 프롬프트 템플릿이 안정되기 전에 멀티 에이전트 런타임을 도입하는 것.

위험:

- 디버깅하기 어려운 자동화
- 잘못 적용된 변경
- 도구 혼란
- 가짜 생산성

---

## 15.5 리뷰 없는 수동 변경

아키텍처, 데이터, 런타임 동작에 영향을 주는 수동 코드 변경을 리뷰와 검증 없이 진행하는 것.

위험:

- 숨은 회귀
- 문서 누락
- 일관성 없는 아키텍처

# 18. Summary — 요약

도구 라우팅은 AI 보조 개발을 통제된 상태로 유지하기 위해 존재한다.

워크플로우는 하나의 도구에게 모든 것을 맡기면 안 된다.

올바른 라우팅은 다음과 같다.

```text
ChatGPT는 판단하고 문서화한다.
Codex는 저장소 컨텍스트를 검사한다.
Copilot은 승인된 파일을 수정한다.
직접 구현은 작고 안전한 정밀 변경을 처리한다.
빌드 / 테스트 도구는 실제 동작을 검증한다.
Git은 이력을 보호한다.
Markdown은 결정을 보존한다.
미래 자동화는 워크플로우가 안정된 뒤로 미룬다.
```
