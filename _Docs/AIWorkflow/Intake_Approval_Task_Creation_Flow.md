# Intake Approval Task Creation Flow

## 1. Purpose

WF-042 adds an explicit task creation path for natural-language intake.

The existing read-only command remains:

```text
/ai intake text:<natural-language work request>
```

The explicit write command is:

```text
/ai intake-create text:<natural-language work request>
```

`/ai intake-create` exists because Discord slash commands cannot support both
`/ai intake text:<...>` and `/ai intake create text:<...>` under the same
subcommand name at the same time.

---

## 2. Behavior

`/ai intake-create`:

1. Classifies the natural-language request with `taskIntakeService`.
2. Builds the same Task Draft used by `/ai intake`.
3. Appends one row to `_Docs/AIWorkflow/Backlog.md`.
4. Creates a timestamped Backlog backup before writing.
5. Returns the created task id and draft summary to Discord.

It does not:

```text
set ActiveTask
approve the task
execute agents
execute Codex CLI
commit
push
modify game source
modify PlayGround/Data
modify _Local
modify node_modules
```

---

## 3. Backlog Mapping

The Backlog row uses:

| Backlog column | Source |
|---|---|
| ID | generated by `taskService` from the suggested category |
| Priority | Task Draft priority |
| Status | `todo` |
| Kind | Task Draft kind |
| Item | Task Draft title |
| Reason | Task Draft reason |
| Tool Route | `Discord intake-create -> human review` |
| Validation | intake draft risk and workflow path note |

The Backlog schema does not have separate risk or workflow path columns, so
those values are recorded in the validation note.

---

## 4. Safety Notes

`taskService` owns Backlog parsing, table row formatting, markdown pipe escaping,
backup creation, and approved write-path checks.

`intakeTaskCreationService` owns only the intake-to-create bridge:

```text
classification -> Task Draft -> createTask input
```

This preserves separation between command dispatch, intake classification,
Backlog mutation, and response formatting.

---

## 5. Validation

Required local validation:

```bat
node --check tools\discord-orchestrator\src\commands\ai.js
node --check tools\discord-orchestrator\src\services\intakeTaskCreationService.js
node --check tools\discord-orchestrator\src\services\taskIntakeService.js
node --check tools\discord-orchestrator\src\services\taskService.js
node --check tools\discord-orchestrator\src\services\responseFormatter.js
npm --prefix tools\discord-orchestrator run register
tools\discord-orchestrator\restart_bot.bat
tools\discord-orchestrator\status_bot.bat
git status --short
git diff --check
git diff --stat
git ls-files | findstr /I "_Local node_modules .env discord_bot.local.json"
```

Required behavior checks:

```text
/ai intake remains read-only.
/ai intake-create appends one Backlog task.
/ai intake-create does not modify ActiveTask.md.
Markdown pipes in intake text are escaped in the Backlog table.
A timestamped Backlog backup is created before writing.
The created task remains todo and is not approved automatically.
```
