# 6. Required Separation of Responsibilities — 책임 분리 원칙

이 워크플로우는 반드시 다음 책임 분리를 유지한다.

```text
Decision / Execution / Data 분리
```

즉, 판단, 실행, 데이터가 한곳에 뒤섞이면 안 된다.

---

## 6.1 Decision — 판단

Decision은 무엇을 할지 결정하는 영역이다.

포함되는 책임은 다음과 같다.

- 무엇을 만들 것인지 결정
- 무엇을 만들지 않을 것인지 결정
- 어떤 구조를 선택할지 결정
- 구현 범위 승인
- AI 산출물 승인 또는 거절
- 변경 사항을 병합해도 되는지 판단

Decision 담당자는 다음과 같다.

- 사용자 / 개발자
- AI 오케스트레이터
- 아키텍트 역할
- 리뷰어 역할

최종 의사결정자는 항상 사용자 / 개발자다.

---

## 6.2 Execution — 실행

Execution은 승인된 결정을 실제로 실행하는 영역이다.

포함되는 책임은 다음과 같다.

- 코드 작성
- 파일 수정
- 빌드 실행
- 테스트 실행
- 변경 적용
- 컴파일 오류 수정
- 프로젝트 파일 갱신

Execution 담당자는 다음과 같다.

- 사용자 / 개발자
- GitHub Copilot Agent Mode
- Codex
- 로컬 스크립트
- 빌드 도구
- 테스트 도구

실행은 반드시 범위와 구조가 승인된 뒤에 수행한다.

---

## 6.3 Data — 데이터

Data는 판단과 실행의 근거가 되는 명시적 자료다.

포함되는 것은 다음과 같다.

- 소스 코드
- JSON 데이터
- Markdown 문서
- Git diff
- 빌드 로그
- 테스트 결과
- Dev Log
- 프롬프트 템플릿
- 아키텍처 결정 기록

프로젝트 워크플로우의 일부가 되는 정보는 채팅창 안에만 남기면 안 된다.

ChatGPT 대화는 임시 작업 공간이다.  
지속 가능한 원본은 Markdown 문서와 Git 이력이다.

# 8. Core Workflow — 기본 워크플로우

표준 AI 오케스트레이터 워크플로우는 다음 순서로 진행한다.

```text
1. 사용자가 작업 요청을 제공한다.
2. 오케스트레이터가 작업 유형을 분류한다.
3. 오케스트레이터가 필요한 역할을 결정한다.
4. 아키텍트가 최종 구조와 축소 범위 구현 구조를 정의한다.
5. 구현 계획자가 수정 파일, 구현 순서, Copilot/Codex 프롬프트를 정의한다.
6. 사용자가 계획을 승인하거나 거절한다.
7. Copilot, Codex, 또는 직접 구현으로 실행한다.
8. 리뷰어가 구조, 런타임 안정성, 데이터 흐름, 회귀 위험을 검토한다.
9. 검증 담당이 빌드, 수동 테스트, 디버그 확인 항목을 정의한다.
10. 사용자가 직접 빌드와 테스트를 실행한다.
11. 문서화 담당이 Dev Log와 남은 리스크를 정리한다.
12. 사용자가 커밋 여부를 결정한다.
```

저위험 작업에서는 일부 단계를 축약할 수 있다.

단, 승인과 리뷰 경계는 명시적으로 유지해야 한다.

---

# 16. Operating Rule — 운영 규칙

사용자가 다음과 같이 말하면:

```text
이 작업에 대해 AI 오케스트레이터 워크플로우 실행해줘.
```

어시스턴트는 단순 구현 제안을 하면 안 된다.

대신 다음 단계를 실행해야 한다.

```text
1. Orchestrator Intake
2. 작업 분류
3. 필요한 역할 결정
4. 설계 단계
5. 구현 계획 단계
6. 사용자 승인 게이트
7. Copilot / Codex 프롬프트 생성
8. 리뷰 기준 생성
9. 검증 기준 생성
10. Dev Log 초안 생성
11. 사용자 액션 목록 생성
```

이 문장은 앞으로 구조화된 AI 팀 워크플로우 실행 트리거로 사용한다.

# 핵심 요약

이 문서에서 반드시 기억해야 하는 기준은 다음이다.

```text
ChatGPT 대화 = 임시 작업 공간
Markdown 문서 = 운영 원본
Git 이력 = 변경 기록
사용자 = 최종 의사결정자
AI = 구조화된 보조 개발팀
```

AI는 작업 속도를 높일 수 있다.  
하지만 아키텍처 판단, 로컬 검증, 최종 책임을 대체하면 안 된다.
