# Dev Log Request

Use this template after meaningful work is completed.

---

## Task Summary

Describe what was done.

```text
Task summary:
...
```

---

## Date

```text
YYYY-MM-DD
```

---

## Files Changed

List files created, modified, moved, or deleted.

```text
Files changed:
...
```

If exact files are not confirmed, state:

```text
Not yet confirmed. Requires Git diff review.
```

---

## Approved Scope

Paste the approved scope.

```text
Approved scope:
...
```

---

## Implementation Summary

Summarize what changed.

```text
Implementation summary:
...
```

---

## Architecture Notes

Describe any architecture decisions or boundaries affected.

```text
Architecture notes:
...
```

If no architecture changed, state:

```text
No architecture change.
```

---

## Review Result

Describe review status.

```text
Review result:
...
```

If review was not performed, state:

```text
Review not performed.
```

---

## Validation Result

Describe build, runtime, manual test, or data validation results.

```text
Validation result:
...
```

If validation was not performed, state:

```text
Validation not performed.
```

If validation was partial, state exactly what was and was not checked.

---

## Remaining Risks

List known risks or unverified areas.

```text
Remaining risks:
...
```

If no risks are known, state:

```text
No known remaining risks.
```

---

## Next Tasks

List follow-up tasks.

```text
Next tasks:
...
```

---

## AI Assistance

Describe meaningful AI assistance if applicable.

Example:

```text
ChatGPT generated the Dev Log draft.
User reviewed, saved, and committed the final document.
No local execution was performed by ChatGPT.
```

---

## Required Output

Generate a Markdown Dev Log suitable for:

```text
_DevLog/FixLog/
```

or another approved Dev Log folder.

---

## Required Assistant Behavior

The assistant must not invent validation results.

The assistant must not claim local execution happened unless the user provided evidence.

The assistant must clearly mark unverified areas.
