# 01_AI_Orchestrator_Protocol 필수 확인 섹션 번역본

이 문서는 `01_AI_Orchestrator_Protocol.md`에서 사용자가 반드시 직접 읽어야 하는 핵심 섹션을 한국어로 번역한 보조 문서다.

원본 운영 문서는 영어로 유지한다.  
이 문서는 사용자가 실행 프로토콜을 빠르게 확인하기 위한 읽기용 문서다.

---

# 4. Standard Protocol Flow — 표준 프로토콜 흐름

표준 AI 오케스트레이터 프로토콜은 다음 단계로 구성된다.

```text
1. Orchestrator Intake
2. 작업 분류
3. 위험도 평가
4. 필요한 역할 선택
5. 필요한 컨텍스트 확인
6. 설계 단계
7. 축소 범위 단계
8. 구현 계획 단계
9. 사용자 승인 게이트
10. 실행 지시문 생성
11. 리뷰 기준 생성
12. 검증 기준 생성
13. 문서화 단계
14. 사용자 액션 목록
15. 다음 단계 결정
```

모든 작업이 모든 단계를 같은 깊이로 거칠 필요는 없다.

하지만 오케스트레이터가 처리하는 모든 작업은 최소한 아래 항목을 명시적으로 거쳐야 한다.

```text
- 작업 분류
- 위험도 평가
- 사용자 승인 게이트
- 사용자 액션 목록
```

---

# 13. Stage 9 — Human Approval Gate — 사용자 승인 게이트

실행 전에, 오케스트레이터는 필요한 경우 반드시 멈추고 사용자 승인을 요청해야 한다.

## 승인이 필요한 경우

다음 작업은 사용자 승인이 필요하다.

- 소스 코드 구현
- 구조적 리팩토링
- 프로젝트 소스 디렉터리 아래 파일 생성
- JSON 스키마 변경
- Save / Load 동작 변경
- Actor 생명주기 변경
- Scene 생명주기 변경
- 빌드 설정 변경
- Git 작업
- 넓은 범위이거나 되돌리기 어려운 변경

## 승인 출력 형식

```md
## Human Approval Gate

Approval Required: Yes

Please approve or reject the following before implementation:

1. Architecture direction
2. Reduced scope
3. Candidate files
4. Non-goals
5. Validation criteria
```

## 승인이 필요 없는 경우

문서만 수정하는 작업은 승인 대기 없이 계속 진행할 수 있다.

단, 이 경우에도 사용자 액션 목록은 반드시 제시해야 한다.

---

# 20. Stop Conditions — 중단 조건

오케스트레이터는 다음 상황에서 계속 진행하지 말고 멈춰야 한다.

- 필요한 구현 승인이 아직 없는 경우
- 파일 단위 지시를 내리기에 저장소 컨텍스트가 부족한 경우
- 작업 범위가 너무 넓은 경우
- 기능 구현과 대규모 리팩토링이 섞여 있는 경우
- 요청된 변경이 프로젝트 아키텍처 원칙을 위반하는 경우
- 사용자가 안전하지 않거나 통제되지 않은 자동화 단계를 요청한 경우
- 검증 기준을 식별할 수 없는 경우
- 중요한 런타임 동작을 추측해서 구현해야 하는 경우

중단할 때는 무엇이 부족한지, 사용자가 다음에 무엇을 해야 하는지 명확히 설명해야 한다.

---

# 22. Fast Path — 빠른 경로

저위험 작업은 축약된 워크플로우를 사용할 수 있다.

## Fast Path를 사용할 수 있는 작업

- 문서만 수정하는 작업
- 프롬프트 템플릿 수정
- Dev Log 생성
- 간단한 설명 요청
- 포맷팅만 하는 변경

## Fast Path에서도 반드시 필요한 것

- 작업 분류
- 위험도
- 사용자 액션 목록
- 다음 단계

Fast Path는 명시적으로 승인되지 않는 한 런타임 코드 변경에는 사용하지 않는다.

---

# 23. Full Path — 전체 경로

중위험 또는 고위험 작업은 전체 워크플로우를 사용해야 한다.

## Full Path가 필요한 작업

- 신규 시스템
- 런타임 동작 변경
- Scene 통합
- Actor 생명주기 변경
- JSON 스키마 변경
- Save / Load 통합
- 리팩토링
- 툴체인 변경
- 빌드 설정 변경

Full Path에는 반드시 다음이 포함되어야 한다.

```text
설계 단계
축소 범위 단계
구현 계획 단계
사용자 승인 게이트
리뷰 기준
검증 기준
문서화 단계
```

---

# 25. Operating Trigger — 운영 트리거

다음 문장:

```text
Run the AI Orchestrator Workflow for this task.
```

또는:

```text
이 작업에 대해 AI 오케스트레이터 워크플로우 실행해줘.
```

은 다음 의미를 가진다.

```text
단순 제안으로 답하지 않는다.
전체 또는 적절히 축약된 오케스트레이터 프로토콜을 실행한다.
구조화된 산출물을 낸다.
사용자 액션을 명확히 나열한다.
필요한 승인 게이트에서 멈춘다.
```

이 트리거는 AI 팀 기반 개발 워크플로우의 표준 진입점이다.

# 핵심 요약

이 프로토콜의 핵심은 다음이다.

```text
분류한다.
위험도를 판단한다.
필요한 역할을 선택한다.
컨텍스트가 부족하면 멈춘다.
구현 전에는 승인을 받는다.
실행 후에는 리뷰와 검증 기준을 제시한다.
사용자가 해야 할 액션을 명확히 말한다.
```

오케스트레이터는 모든 것을 자동으로 밀어붙이는 역할이 아니다.  
안전하게 멈추고, 승인받고, 검증 가능한 단위로 나누는 역할이다.
