# AIWorkflow LLM Wiki 사용자 가이드

## 1. LLM Wiki가 뭐야?

LLM Wiki는 AIWorkflow Studio의 **회사 기억**이다.

내가 Codex와 나눈 중요한 대화, 회의 결과, 반려한 아이디어, 공식 방향,
실패에서 배운 점, 외부 조사 결과를 사람이 읽을 수 있는 Markdown 문서로
남기는 공간이다.

쉽게 말하면:

```text
그때 무슨 결정을 했더라?
왜 그 방향은 버렸더라?
AI 직원에게 앞으로 어떤 맥락을 줘야 하지?
```

이 질문에 답하기 위한 기억 저장소다.

## 2. RAG랑 뭐가 달라?

RAG는 큰 문서 더미에서 필요한 조각을 검색하는 방식에 가깝다.

LLM Wiki는 AI Librarian이 내용을 읽고, 요약하고, 연결하고, 사람이 검토할 수
있는 지식 문서로 정리하는 방식이다.

지금 단계에서는 RAG보다 LLM Wiki가 먼저다.

이유:

- 프로젝트 규모가 아직 사람이 읽고 관리할 수 있는 수준이다.
- 중요한 것은 단순 검색보다 “왜 그런 결정을 했는지”다.
- AI 직원에게 단편 조각보다 정리된 맥락을 주는 것이 더 안정적이다.

## 3. 어디에 저장돼?

기본 위치:

```text
_Docs/AIWorkflow/StudioWiki/
```

주요 폴더:

| 폴더 | 의미 |
|---|---|
| `Inbox` | 아직 분류하지 않은 원본 메모 |
| `Research` | 외부 조사, 참고 자료, 도구 조사 |
| `Proposals` | 아직 채택되지 않은 제안 |
| `Decisions` | 내가 내린 결정 |
| `Canon` | 공식 설정, 공식 방향, 승인된 사실 |
| `Lessons` | 다시 써먹을 수 있는 교훈 |
| `Rejected` | 반려한 아이디어와 이유 |
| `Concepts` | Studio, Work Packet 같은 개념 정의 |

## 4. 중요한 규칙

원본 대화나 AI 직원 의견은 바로 공식 설정이 아니다.

흐름은 항상 이렇다.

```text
원본 자료
-> AI Librarian 정리
-> 내가 검토
-> Wiki 기록으로 승격
```

공식 설정이나 공식 방향으로 확정하려면 반드시 Human Director 결정이 필요하다.

## 5. 내가 실제로 하는 일

평소에는 이 정도만 하면 된다.

1. 중요한 대화나 결론이 나오면 “이건 Wiki에 남겨야 한다”고 지시한다.
2. AI Librarian이 어디에 넣을지 초안을 만든다.
3. 나는 이것을 공식 설정, 제안, 교훈, 반려 기록 중 무엇으로 둘지 판단한다.
4. 확정된 기록은 다음 회의나 작업 지시의 맥락으로 쓰인다.

## 6. Studio에서 바로 남기는 방법

Studio의 `기록실`에는 `Wiki Inbox에 남기기`가 있다.

이 기능은 대화, 자문, 조사, 작업 중 “나중에 다시 써야 할 것 같은 맥락”을
`_Docs/AIWorkflow/StudioWiki/Inbox/` 아래 Markdown 문서로 남긴다.

중요한 점:

- 저장되는 것은 정리 대기 문서다.
- 공식 결정이나 공식 설정으로 확정되지 않는다.
- task 생성, 소스 수정, commit/push는 하지 않는다.
- 나중에 AI Librarian 또는 Human Director가 읽고 `Decisions`, `Canon`,
  `Lessons`, `Research`, `Rejected` 같은 위치로 승격할지 판단한다.

즉, `Wiki Inbox에 남기기`는 “잊어버리지 않게 임시로 붙잡아 두는 입구”다.

Inbox에 쌓인 문서는 Studio에서 `승격 계획`을 눌러 읽기 전용으로 먼저 점검한다.

`승격 계획`은 해당 문서를 `Decisions`, `Canon`, `Lessons`, `Research`,
`Proposals`, `Concepts` 중 어디로 옮기는 것이 자연스러운지 추천한다.
이 버튼은 실제 파일 이동, 공식 설정 확정, task 생성, 소스 수정, commit/push를 하지 않는다.
최종 승격은 Human Director가 의미와 위험을 확인한 뒤 별도 흐름으로 처리한다.

## 7. Studio와의 관계

Studio는 운영본부다.

LLM Wiki는 회사 기억이다.

Studio가 일을 진행할 때 LLM Wiki에서 필요한 기억을 꺼내 Context Pack에 넣는다.

예:

```text
새 게임 방향 논의
-> 과거에 반려한 전투 아이디어 확인
-> 승인된 세계관 설정 확인
-> 최근 QA 교훈 확인
-> 직원 회의에 전달
```

## 8. Obsidian은 어떤 역할이야?

Obsidian은 읽고 탐색하기 좋은 도구다.

하지만 Obsidian이 권한을 갖는 것은 아니다.

권한 구조는 그대로다.

```text
결정권: Human Director
운영 기록: Studio
기억 저장: LLM Wiki
읽기 도구: Obsidian
```

## 9. 하면 안 되는 것

- AI가 쓴 내용을 바로 공식 설정으로 믿지 않는다.
- 제안을 결정처럼 쓰지 않는다.
- 반려된 아이디어를 삭제하지 않는다.
- Wiki를 task 목록처럼 쓰지 않는다.
- Wiki 기록만 보고 commit/push를 승인하지 않는다.

## 10. 좋은 기록의 기준

좋은 Wiki 기록은 짧고 명확하다.

기록에는 보통 이것이 있어야 한다.

- 무엇에 대한 기록인지
- 왜 중요한지
- 어디서 나온 내용인지
- 공식인지, 제안인지, 반려인지
- 다음에 누가 참고해야 하는지

## 11. 지금 단계의 목표

지금 목표는 완전한 자동 지식 시스템이 아니다.

1차 목표는:

```text
중요한 맥락이 사라지지 않게 한다.
AI 직원이 과거 결정을 반복해서 잊지 않게 한다.
내가 다시 설명해야 하는 양을 줄인다.
```
