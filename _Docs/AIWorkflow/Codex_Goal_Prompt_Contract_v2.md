# Codex Goal Prompt Contract v2

## Purpose

Codex Goal Prompt Contract v2 standardizes the markdown generated by:

```text
/ai prepare goal
```

The contract is intended to make Codex CLI `/goal` executions repeatable,
auditable, and safe. It should reduce premature completion, overbroad
implementation, unsafe automation, and missing validation evidence.

---

## Required First Line

Every generated `goal_request_*.md` file must start with a concise, usable
Codex CLI command:

```text
/goal <Verb> <TaskId>: <Task title>
```

The command must be manually reviewed and pasted by the human. Discord must not
execute Codex CLI automatically.

---

## Required Sections

Generated files must include these sections in order:

```text
1. Goal Header
2. Objective
3. Task Context
4. Project Context
5. Scope
6. Non-goals
7. Execution Mode
8. Safety Constraints
9. Human Decision Gates
10. Subagent Policy
11. Validation Plan
12. Stop Conditions
13. Completion Audit
14. Required Return Format
```

---

## Mode-Aware Scope

The `Scope` and `Execution Mode` sections must reflect the selected mode:

```text
analysis:
  inspect and report only
  no file modifications

implementation:
  modify only approved task files
  keep changes bounded and validated

prototype:
  create isolated prototype or experiment only if requested
  keep prototype aligned with final-form architecture

review:
  inspect current diff and risks only
  no file modifications unless human explicitly asks for fixes
```

---

## Required Non-Goals

Every generated request must explicitly prohibit:

```text
no commit
no push
no release
no secret exposure
no unrelated source edits
no _Local
no node_modules
no external agent execution unless explicitly approved
```

---

## Human Decision Gates

Generated requests must require human approval before:

```text
schema changes
save format changes
broad architecture changes
external tool installation
computer-use actions
credential/login/subscription setup
destructive commands
commit/push/release
```

---

## Subagent Policy

Default policy:

```text
analysis/review:
  read-only subagents allowed if useful

implementation:
  subagents may analyze/review
  subagents must not modify files unless explicitly approved for bounded scope

prototype:
  subagents allowed for planning/review
```

If subagents are used, the final orchestrator must consolidate their findings
before declaring completion.

---

## Validation Plan

Every generated request must include:

```text
git status --short
git diff --check
git diff --stat
```

Task-specific validation should be included when available from `Backlog.md`.

Additional rules:

```text
data-related tasks:
  tools\aiworkflow\json_smoke_check.bat

Discord command schema changes:
  npm --prefix tools\discord-orchestrator run register
  tools\discord-orchestrator\restart_bot.bat
  tools\discord-orchestrator\status_bot.bat

game runtime behavior changes:
  request human runtime validation
```

---

## Completion Audit

Before declaring complete, Codex must verify:

```text
objective satisfied
non-goals respected
files changed are in scope
validation commands run or explicitly not run with reason
risks documented
no commit performed
final git status reported
```

---

## Required Return Format

Codex responses should return:

```text
1. Implementation summary
2. Files changed
3. Contract v2 behavior, or analysis/review summary if no implementation was done
4. Validation commands run
5. Validation results
6. Known risks
7. Human decisions needed
8. Commit recommendation
```
