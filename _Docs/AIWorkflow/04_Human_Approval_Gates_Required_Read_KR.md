# 04_Human_Approval_Gates 필수 확인 섹션 번역본

이 문서는 `04_Human_Approval_Gates.md`에서 사용자가 반드시 직접 읽어야 하는 핵심 섹션을 한국어로 번역한 보조 문서다.

원본 운영 문서는 영어로 유지한다.  
이 문서는 AI가 어디까지 자동으로 진행해도 되고, 어디서 반드시 멈춰야 하는지 빠르게 확인하기 위한 읽기용 문서다.

---

# 2. Core Principle — 핵심 원칙

핵심 원칙은 다음이다.

```text
AI는 추천할 수 있다.
AI는 준비할 수 있다.
AI는 리뷰할 수 있다.
AI는 프롬프트를 생성할 수 있다.
프로젝트를 변경하는 실행 전에는 사용자 승인이 필요하다.
```

워크플로우는 생성된 계획을 사용자가 승인한 것으로 취급하면 안 된다.

승인은 대화 안에서 명확히 드러나거나, 저장된 워크플로우 문서 안에 명시되어야 한다.

---

# 3. Approval Gate Types — 승인 게이트 유형

워크플로우는 다음 승인 게이트를 사용한다.

```text
Design Approval Gate
Scope Approval Gate
File Modification Approval Gate
Data Schema Approval Gate
Runtime Behavior Approval Gate
Tool Execution Approval Gate
Review Acceptance Gate
Validation Acceptance Gate
Commit Approval Gate
Workflow Rule Update Gate
```

각 게이트는 서로 다른 프로젝트 경계를 보호한다.

---

# 4. Design Approval Gate — 설계 승인 게이트

## 목적

설계 승인 게이트는 아키텍처 결정을 보호한다.

설계 제안을 구현 계획으로 바꾸기 전에 사용해야 한다.

## 승인이 필요한 경우

- 새 시스템을 도입하는 경우
- 기존 시스템의 책임 경계가 바뀌는 경우
- 소유권 또는 생명주기 규칙이 바뀌는 경우
- Decision / Execution / Data 책임이 재분배되는 경우
- 축소 범위 구현을 선택하는 경우
- 장기 확장 경로를 정의하는 경우
- 설계 결정이 미래 작업에 영향을 주는 경우

## 승인받아야 하는 항목

- 최종형 아키텍처
- 축소 범위 구현
- 책임 경계
- 데이터 흐름
- 소유권과 생명주기 규칙
- 명시적 non-goals
- 나중으로 미룬 결정

---

# 5. Scope Approval Gate — 범위 승인 게이트

## 목적

범위 승인 게이트는 작업이 통제 없이 확장되는 것을 막는다.

Codex, Copilot, 또는 직접 구현용 실행 지시문을 만들기 전에 사용해야 한다.

## 승인이 필요한 경우

- 현재 범위와 미래 범위가 함께 있는 경우
- 하나의 기능이 주변 시스템으로 확장될 가능성이 있는 경우
- 요청 작업 주변에 여러 시스템이 붙어 있는 경우
- 이번 단계에서 제외할 작업을 제안하는 경우
- 작업이 넓은 리팩토링으로 번질 수 있는 경우

## 승인받아야 하는 항목

- 지금 구현할 것
- 지금 구현하지 않을 것
- 미래 확장 지점
- 명시적으로 제외할 시스템
- 중단 조건
- 완료 기준

---

# 6. File Modification Approval Gate — 파일 수정 승인 게이트

## 목적

파일 수정 승인 게이트는 의도하지 않은 저장소 변경을 막는다.

Copilot, Codex 또는 다른 도구가 파일을 수정하기 전에 사용해야 한다.

## 승인이 필요한 경우

- 소스 파일 생성
- 소스 파일 수정
- 프로젝트 파일 수정
- 데이터 파일 수정
- 빌드 파일 수정
- 기존 문서 재정리
- AI 생성 변경을 저장소에 적용

## 승인받아야 하는 항목

- 생성 허용 파일
- 수정 허용 파일
- 명시적으로 수정 금지할 파일
- 최대 예상 파일 범위
- 관련 없는 리팩토링 금지 여부
- 포맷팅만 하는 변경 허용 여부

---

# 7. Data Schema Approval Gate — 데이터 스키마 승인 게이트

## 목적

데이터 스키마 승인 게이트는 구조화된 프로젝트 데이터를 보호한다.

JSON 스키마, 직렬화 데이터, 저장 데이터, enum 직렬화, 리소스 경로 규칙, 에셋 메타데이터 규칙을 변경하기 전에 사용한다.

## 승인이 필요한 경우

- 새 JSON 스키마 추가
- 기존 JSON 필드 이름 변경, 제거, 의미 변경
- Save / Load 데이터 변경
- enum 값 직렬화 또는 변경
- 리소스 경로 규칙 변경
- 에셋 메타데이터 구조 변경
- 콘텐츠 호환성에 영향 가능

## 승인받아야 하는 항목

- 새 필드 또는 변경 필드
- 필드 의미
- 필수 필드 / 선택 필드 여부
- 기본값
- 하위 호환성 정책
- 잘못된 데이터에 대한 로더 동작
- 디버그 / assert 동작
- 마이그레이션 필요 여부

---

# 8. Runtime Behavior Approval Gate — 런타임 동작 승인 게이트

## 목적

런타임 동작 승인 게이트는 게임플레이와 엔진 동작을 보호한다.

런타임 상태, Update 순서, 객체 생명주기, Scene 동작, Actor 동작, UI 동작, 게임플레이 로직에 영향을 줄 수 있는 변경 전에 사용한다.

## 승인이 필요한 경우

- Actor 상태 전이 변경
- Scene 초기화 또는 정리 변경
- Update 순서 변경
- Render 순서 변경
- 이동, 공격, 피격, 사망, 스폰, 상호작용 동작 변경
- UI 입력 또는 Update 동작 변경
- 다이얼로그 진행 동작 변경
- 스킬 또는 적 동작 변경
- 객체 소유권, 등록, 파괴 변경

## 승인받아야 하는 항목

- 런타임 동작 변경
- 상태 전이 변경
- 생명주기 규칙
- Update 순서 가정
- 실패 처리
- 디버깅 지점
- 회귀에 민감한 영역

---

# 9. Tool Execution Approval Gate — 도구 실행 승인 게이트

## 목적

도구 실행 승인 게이트는 외부 도구 또는 로컬 도구 사용 시점을 통제한다.

Copilot, Codex 또는 프로젝트 파일을 검사, 생성, 수정할 수 있는 도구에 프롬프트를 전달하기 전에 사용한다.

## 승인이 필요한 경우

- Copilot Agent Mode가 파일을 수정할 예정
- Codex가 저장소를 검사할 예정
- Codex가 패치를 생성할 예정
- 빌드 명령을 실행할 예정
- 스크립트가 프로젝트 파일을 수정할 예정
- 미래 자동화 도구가 저장소에 작동할 예정

## 승인받아야 하는 항목

- 사용할 도구
- 도구 사용 목적
- 도구 권한
- 파일 수정 가능 여부
- 기대 산출물
- 중단 조건
- 사용자 액션

---

# 10. Review Acceptance Gate — 리뷰 수용 게이트

## 목적

리뷰 수용 게이트는 구현된 변경을 받아들여도 되는지 판단한다.

소스 변경, 생성 패치, 의미 있는 문서 변경 이후 사용한다.

## 승인이 필요한 경우

- Git diff를 리뷰한 경우
- AI 생성 코드를 리뷰한 경우
- Critical 또는 Major 이슈가 발견된 경우
- 런타임 동작이 변경된 경우
- 아키텍처 또는 데이터 흐름이 변경된 경우
- 검증으로 넘어가기 전에 수정이 필요한지 결정해야 하는 경우

## 사용자가 결정해야 하는 항목

- Critical 이슈가 해결되었는가
- Major 이슈가 해결되었거나 수용되었는가
- Minor 이슈를 뒤로 미룰 것인가
- diff가 리뷰 가능한가
- 관련 없는 변경이 없는가
- 검증으로 넘어갈 수 있는가

---

# 11. Validation Acceptance Gate — 검증 수용 게이트

## 목적

검증 수용 게이트는 작업이 실제로 확인되었는지 판단한다.

빌드 확인, 런타임 확인, 수동 테스트, 데이터 검증 이후 사용한다.

## 승인이 필요한 경우

- 런타임 동작이 변경된 경우
- 데이터 로딩이 변경된 경우
- AI 생성 코드가 적용된 경우
- 수동 검증이 필요한 경우
- 빌드 또는 런타임 실패가 발생한 경우
- 작업 완료 여부를 판단하는 경우

## 사용자가 확인해야 하는 항목

- 빌드 결과
- 런타임 테스트 결과
- 수동 테스트 결과
- 데이터 로딩 결과
- 관찰된 실패 증상
- 수행한 회귀 체크
- 아직 확인하지 못한 영역

---

# 12. Commit Approval Gate — 커밋 승인 게이트

## 목적

커밋 승인 게이트는 Git 이력을 보호한다.

사용자에게 커밋을 추천하기 전에 사용한다.

## 승인이 필요한 경우

- 작업 완료로 간주되는 경우
- 문서가 추가 또는 수정된 경우
- 소스 변경이 구현된 경우
- Dev Log가 작성된 경우
- 워크플로우 규칙이 변경된 경우
- 파일이 이동 또는 재정리된 경우

## 사용자가 확인해야 하는 항목

- Git status에 의도한 변경만 있는가
- diff를 리뷰했는가
- 검증이 통과했거나, 남은 공백을 수용했는가
- 필요한 경우 Dev Log가 있는가
- 커밋 범위가 일관적인가
- 커밋 메시지가 적절한가

---

# 15. Explicit Approval Language — 명시적 승인 표현

사용자는 다음과 같이 명확한 표현으로 승인할 수 있다.

```text
Approved.
Proceed.
Go ahead.
진행.
승인.
그 범위로 진행.
이대로 Copilot 프롬프트 만들어줘.
```

불확실한 표현은 완전한 승인으로 취급하지 않는다.

애매한 예시는 다음과 같다.

```text
Looks okay.
Maybe.
괜찮은 듯?
일단 보자.
나쁘지 않네.
```

승인이 애매하면 어시스턴트는 명시적인 확인을 요청하거나, 실행 없는 초안 작업만 진행해야 한다.

---

# 16. Approval Scope — 승인 범위

승인은 해당 게이트에서 설명한 특정 범위에만 적용된다.

승인은 자동으로 아래 항목까지 포함하지 않는다.

- 추가 파일
- 관련 리팩토링
- 미래 시스템
- 추가 기능
- 데이터 스키마 확장
- 빌드 설정 변경
- 명시된 권한을 넘어선 도구 실행

범위가 바뀌면 새로운 승인 게이트가 필요하다.

---

# 17. Default Policy When Unsure — 불확실할 때의 기본 정책

승인이 필요한지 불확실하면, 승인 필요로 간주한다.

기본 정책은 다음이다.

```text
작업이 프로젝트 상태를 바꾸면 승인을 요청한다.
작업이 초안 작성이나 설명만 한다면 진행하고 사용자 액션을 나열한다.
범위가 불명확하면 범위를 좁히고 승인을 요청한다.
```

---

# 20. Completion Criteria — 완료 기준

작업은 다음 조건을 만족해야 완료로 간주할 수 있다.

- 필요한 승인을 받았다.
- 구현이 승인된 범위 안에 머물렀다.
- 리뷰를 수행했다.
- 검증을 수행했거나 명시적으로 뒤로 미뤘다.
- 필요한 경우 문서화를 했다.
- 남은 리스크를 알고 있다.
- 사용자가 커밋 여부를 결정했다.

AI는 코드나 계획을 생성했다는 이유만으로 작업 완료를 선언하면 안 된다.

---

# 핵심 요약

Human Approval Gate는 다음을 보호하기 위해 존재한다.

```text
아키텍처
범위
파일
데이터 스키마
런타임 동작
도구 실행
리뷰 품질
검증 품질
Git 이력
워크플로우 규칙 일관성
```

위험이 낮으면 빠르게 진행할 수 있다.

하지만 프로젝트 상태, 아키텍처, 데이터, 런타임 동작, Git 이력에 영향을 줄 수 있다면 반드시 멈춰야 한다.
