목적

파티클 리소스는 작은 장식 이미지가 아니라 게임 안에서 특정 정보를 전달하는 시각 재료다. 따라서 먼저 모양을 정하지 말고, 파티클이 플레이어에게 무엇을 전달해야 하는지부터 정한다.

핵심 규칙: 역할을 먼저 정하고, 제작 방식을 고른 뒤, 계열과 형태를 디자인한다.

요청 순서

1. 목적
   이 파티클이 게임에서 무엇을 전달해야 하는가?

2. 제작 방식
   발광형 / 카툰형 / 플립북형 중 무엇인가?

3. 계열
   발광, 타격, 마법, 연기, 불꽃, 트레일 등 어떤 계열인가?

4. 판독성
   잘 보여야 하는가, 은은해야 하는가, 배경에 섞여도 되는가?

5. 기술 사양
   크기, 색상 방식, 알파 방식, 파일명, 저장 경로를 정한다.

6. 사용 방식
   런타임 tint 여부, blend 예상, JSON 연결 여부를 정한다.

계열별로 모든 제작 방식 버전을 만들 필요는 없다. 실제 사용 목적이 있는 조합만 만든다.

제작 방식

방식 목적 RGB/Alpha 기준 적합한 예
발광형 분위기, aura, glow, 은은한 보조광 RGB는 밝은 회색에서 흰색 중심. Alpha는 부드러운 그라데이션. 외곽선은 거의 없음. Glow_Soft, Halo, MagicGlow
카툰형 판독성, 타격감, 액션 피드백 RGB는 어두운 외곽, 중간톤, 밝은 코어 구조. Alpha는 부드럽게 유지. HitStar, ShockRing, FirePop, VisibleFlare
플립북형 시간에 따른 형태 변화, 연기, 폭발, 큰 불꽃 여러 프레임의 RGB/Alpha가 시간에 따라 변화. 외곽선은 효과 성격에 따라 결정. SmokeBurst_4f, Explosion_6f, FireLoop_8f
현재 프로젝트의 일반 alpha blend + tint 경로에서는 순수 발광형이 배경에 묻을 수 있다. 명확한 피드백용 이펙트는 카툰형을 우선 검토한다.

계열별 기본 선택

계열 권장 방식 설계 메모
기본 발광 발광형 + 일부 카툰형 은은한 보조광은 발광형, 눈에 띄어야 하는 flare는 카툰형으로 분리한다.
충돌/타격 카툰형 어두운 외곽 또는 명확한 밴드를 넣어 피격 판독성을 확보한다.
마법/에너지 발광형 + 카툰형 분위기용 glow와 피드백용 spark를 역할별로 나눈다.
연기/먼지 카툰형, 필요 시 플립북형 초기에는 단일 puff로 충분하다. 큰 먼지나 연기는 플립북형을 검토한다.
불/열기 카툰형, 큰 효과는 플립북형 작은 ember나 fire pop은 카툰형, 폭발이나 지속 불꽃은 플립북형이 적합하다.
트레일/속도선 카툰형 중심 움직임이 읽혀야 하면 외곽 밴드를 둔다. 은은한 잔상은 발광형도 가능하다.

프로젝트 기본값

기본 크기 64x64
포맷 PNG, Format32bppArgb
배경 투명
색상 흰색 또는 회색 기반 tintable 리소스
Alpha 외곽 블렌딩을 위해 부드럽게 유지
카툰형 RGB 어두운 외곽 + 중간톤 + 밝은 중심. 보이는 최외곽에는 필요 시 0~64 범위의 어두운 밴드를 둔다.
기본 저장 위치 PlayGround/Data/Resources/Textures/Particles
기본 범위 리소스 파일 생성만. JSON 연결, 런타임 코드 수정, 렌더링 정책 변경은 별도 승인 범위로 다룬다.

요청 템플릿

파티클 리소스 생성 요청

목적:
- 예: 적 피격 순간을 명확하게 보여주는 타격 이펙트

제작 방식:
- 카툰형

계열:
- 충돌/타격

필요 리소스:
- HitStar
- ShockRing
- ImpactDot

시각 규칙:
- 어두운 외곽이 있어야 함
- 중심은 밝게
- Alpha는 부드럽게 유지
- RGB는 3~4단계 포스터화

기술 사양:
- 64x64
- PNG
- Format32bppArgb
- 투명 배경
- White/tintable 기반
- 저장 경로: PlayGround/Data/Resources/Textures/Particles

범위:
- 리소스 파일만 생성
- JSON 연결 없음
- 런타임 코드 수정 없음

짧은 요청 예시

카툰형 타격 파티클 3종 만들어줘.
목적은 적 피격 판독성이고, 64x64 PNG, 투명 배경, tint 가능해야 해.
어두운 외곽 + 중간톤 + 밝은 코어 구조로 만들고,
JSON이나 코드 수정은 하지 말고 리소스만 생성해줘.

검수 기준

  • 요청 목적이 문서 또는 Dev Log에 남아 있는지 확인한다.
  • 파일이 64x64, Format32bppArgb, 투명 배경인지 확인한다.
  • 카툰형은 배경 위에서 실루엣이 읽히는지 확인한다.
  • 발광형은 너무 희미해서 게임 화면에서 사라지지 않는지 확인한다.
  • 플립북형은 프레임 순서, 루프 여부, 가장자리 깜빡임을 확인한다.
  • 리소스 생성만 요청한 경우 JSON, 런타임 코드, 렌더링 코드를 수정하지 않았는지 확인한다.
  • 리소스 폴더가 Git ignore 대상이면 커밋 시 git add -f가 필요한지 확인한다.
AIWorkflow 사용자 가이드는 이 문서 변경으로 갱신하지 않는다. 이 문서는 파티클 리소스 제작 요청 가이드이며, AIWorkflow 명령, 승인, PC Runner, 완료 게이트, 사용자 개입 지점을 변경하지 않는다.
