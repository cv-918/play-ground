# Copilot Instructions (Optimized)

## 1. Core Rules (Non-Negotiable)

- Always design final-form architecture first
- Reduced scope MUST preserve same structure
- NO temporary solutions or future refactor assumptions

---

## 2. Separation of Concerns

All systems MUST separate:

- Decision (logic selection)
- Execution (action)
- Data (state)

Forbidden:
- Logic inside data
- Execution inside decision
- Actor as logic hub

---

## 3. Structural Constraints

- No large if/switch accumulation in a single class
- Prefer composable modular components
- Avoid monolithic class design
- No abstraction without structural benefit

---

## 4. System Requirements

All outputs MUST include:

- Responsibility boundaries (who owns what)
- Data flow (input → decision → execution → output)
- Concrete implementation (code-level)
- Explicit tradeoff if design choice exists

---

## 5. Domain Contracts

### FSM

Structure:
- State (pure)
- Transition (condition)
- Decision (external evaluation)
- Controller (state change)
- Context (data)

Forbidden:
- State changing state directly
- State containing branching logic explosion

---

### UI

Structure:
- View (render only)
- ViewModel (presentation data)
- Controller (input handling)
- Model (core data)

Forbidden:
- Logic in View
- Direct gameplay access from UI

---

### ACTOR

Structure:
- Decision (behavior selection)
- Execution (behavior execution)
- Component (modular unit)
- Data (state)

Forbidden:
- Actor as central logic hub
- switch-based behavior dispatch

---

## 6. Mode Contract

### FAST

- Architecture only
- Components + responsibilities
- Minimal data flow (3~5 lines)
- No code

---

### ARCH

- Full structure
- Responsibility separation
- Data flow included
- Interface-level code only

---

### FULL

- Full structure
- Detailed data flow
- State / interaction logic
- Complete implementation code
- Tradeoff analysis

---

## 7. Mode Selection Rules

- Pattern / standard structure → FAST
- Design choice required → ARCH
- Hard to refactor / correctness critical → FULL

---

## 8. Workflow

1. FAST → structure
2. ARCH → design
3. FULL → validation

---

## 9. Constraints

- C++
- Prefer C++14 compatibility
- Low-level rendering context assumed (e.g., DX9, WinAPI)

---

## 10. Output Requirements

All responses MUST be:

- Structurally consistent
- Traceable
- Implementation-ready
- Non-abstract
